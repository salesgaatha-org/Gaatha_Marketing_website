The service

What is Web & Mobile App Design?

Web and mobile app design is the work of deciding what an app does for its users and how it feels to use — the flows, screens, states, interactions and visual system — and documenting it so developers can build it exactly. UI is what the user sees; UX is whether they get where they need to go without thinking. Good app design is decided in flows and prototypes, long before code.

At gaa-tha app design is treated as a product problem with a brand on top. We map the jobs the app must do, wireframe the flows, test a clickable prototype with real users, then design the full UI in your identity as a component-based system with tokens developers can implement. Admin consoles and dashboards get the same care, because the people running the business use them every day.

Scope

What's included

  • Discovery — users, jobs to be done, business rules, existing systems and success metrics
  • User flows, information architecture and low-fidelity wireframes
  • Clickable prototype in Figma for user testing and stakeholder sign-off
  • UI design for every screen and state — empty, loading, error, success — on mobile and desktop
  • Design system with components, colour and type tokens, spacing and icon set
  • Admin console and analytics dashboard design, including data tables, filters and charts
  • Developer handover — specifications, assets, interaction notes and Figma dev mode access
  • Web app development in-house (front end, back end, database, authentication and integrations)
  • QA support during your native iOS or Android build, and design fixes after launch
  • App store listing assets — icons, screenshots and copy — where the app is published

Process

How we work

Five steps, in the order they happen.

01

Discovery

We interview users and stakeholders, list the jobs the app must do and the business rules behind them, and agree scope and success metrics.

02

Flows and wireframes

User flows and low-fidelity wireframes are drawn for every journey, reviewed with your team and corrected before any visual design.

03

Prototype and test

A clickable prototype is tested with a handful of real users; confusion and dead ends are fixed while they are still cheap to fix.

04

UI and design system

Every screen and state is designed in your brand as a component-based system with tokens, ready for development.

05

Build and handover

Web apps are developed, tested and launched by us; for native apps we hand over specifications and assets and support your developers through build and QA.

Outputs

Deliverables you receive

  • User flows, information architecture and wireframes
  • Clickable Figma prototype with user-testing notes
  • Full UI designs for all screens and states
  • Design system with components and tokens
  • Developer handover package (specs, assets, interaction notes)
  • Launched web app, or QA support for native builds

Good to know

Questions about App design

Answer-first, so humans and AI assistants get the point quickly.

UX (user experience) design decides how an app works — the flows, structure and logic that get a user to their goal without friction. UI (user interface) design decides how it looks — layout, colour, type, components and states. gaa-tha does both, testing the UX in a clickable prototype before the UI is finalised in your brand.

A website presents information and captures enquiries; a web app lets logged-in users do things — place orders, track jobs, manage inventory, view dashboards. Web apps need user roles, data, integrations and many more screen states, which is why they are designed as systems rather than pages.

Three to six weeks for UX and UI on a typical app or admin console: about a week each for discovery and flows, one to two for the prototype and testing, and one to three for full UI and the design system. Web app development then takes six to twelve weeks depending on scope and integrations.

Web apps, admin consoles and dashboards are developed in-house. For native iOS and Android apps we deliver a complete developer-ready package and stay on through your developers' build and QA, so the product ships as designed.

It depends on the number of screens, user roles, integrations and whether you need design only or design plus development, so we quote by phase after a discovery call rather than a flat rate. Design-only engagements can start small with a prototype and grow as the product is validated.
