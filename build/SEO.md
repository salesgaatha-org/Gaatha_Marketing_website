# Search engines, sitemap and social previews

How gaa-tha.com is set up for Google, Bing and link previews, and what is
manual versus automatic.

## Status (Nov 2026)

| Item | State |
|---|---|
| Google Search Console | Domain verified with a DNS TXT record (`google-site-verification=…` on gaa-tha.com). |
| Bing Webmaster Tools | Verified with the `msvalidate.01` meta tag in `index.html` — keep that tag. |
| Sitemap | `https://gaa-tha.com/sitemap.xml`, regenerated by `node build/build.js`, listed in `robots.txt`. |
| IndexNow (Bing, Yandex, Seznam, Naver, Yep) | Automatic: the deploy workflow runs `build/indexnow.js` after every publish. Key file: `/c6e4bff1e33a55dde022f7b98bd08076.txt`. |
| Social previews (Open Graph / X) | Generated for every page by `socialMeta()` in `build/build.js`. |
| Favicons | `/favicon.ico`, `/assets/icons/*`, `/site.webmanifest`. |

## One-time manual steps (need an owner login)

1. **Google Search Console** → property `gaa-tha.com` → *Sitemaps* → submit
   `https://gaa-tha.com/sitemap.xml`. Check *Pages* for "Discovered – not
   indexed" and use *URL inspection → Request indexing* for the most
   important pages (home, /services, the top service pages).
2. **Bing Webmaster Tools** → site `https://gaa-tha.com/` → *Sitemaps* →
   submit `https://gaa-tha.com/sitemap.xml`. Under *IndexNow* you should see
   the URLs pushed by the deploy workflow. (Shortcut: *Import from Google
   Search Console* copies the site and sitemap in one click.)
3. To push **every** URL to Bing again, run the *Deploy to Netlify* workflow
   manually from the GitHub Actions tab (manual runs submit the whole sitemap).
4. After changing previews, refresh caches:
   [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) (also
   refreshes WhatsApp/Instagram) and
   [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/).

Google retired its sitemap "ping" endpoint in 2023 and does not use IndexNow,
so Google picks up changes from the sitemap submitted in Search Console.

## Social preview rules (enforced by the build)

Every page carries the same block: `og:site_name` = gaa-tha, `og:locale` =
`en_IN`, title/description/URL equal to the page's canonical values, a
1200×630 image with `og:image:width`, `height`, `type` and `alt`, and X/Twitter
tags that mirror the Open Graph ones exactly. Articles also carry
`article:published_time`, `modified_time` and `article:publisher` (the
Facebook page from `content/site.json`).

- Hand-written root pages (`index.html`, `about.html`, …): edit `og:title`,
  `og:description` or `og:image` in the page; the next build rebuilds the
  rest of the block from those values.
- Generated pages: the title and description come from `content/`, the image
  from the page's `og` image (`assets/og/services/`, `assets/og/blog/`) or
  `assets/og-default.jpg`.
- New share images must be **1200×630 JPG**; the build warns otherwise.
